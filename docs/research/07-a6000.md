# a6000-fw-decomp

Source: the clone of nicolvus/a6000-fw-decomp at `~/git/nicolvus/a6000-fw-decomp`, HEAD `8ba5e102` (2026-11-24). Citations with the prefix `a6000/` point into that clone. The repo is in Spanish. Each quote is an ASCII part of a source line, and the English next to it is a translation.

## Summary

- The project is firmware research on a Sony camera with patched firmware flashed to real hardware. It is not a matching decompilation, and it has no compile-and-compare gate.
- It has the largest agent history in this set: 1,513 commits in 35 days, with Claude Code, Codex, OpenCode and Copilot.
- It has no launcher, no loop, no hook, no time limit and no budget. Its long runs were started by a person.
- It has the best state-keeping in this set: a short "current state" file that a session reads first, a fixed order for writing state back, a task file per delegated run with a live checkpoint, and a rule that a timeout is not a reason to ask a human.
- It keeps one Ghidra analysis alive in a daemon with a restart policy, because REA does not keep analysis between sessions.

## 4. The loop

The loop is prose in `CLAUDE.md`, `docs/STATE.md` and the briefs. No script runs it.

1. Read `knowledge/CURRENT.md`, then the rows of the task ledger that matter.
2. Take a row of `docs/PENDIENTES.md` (`a6000/docs/PENDIENTES.md:25` "| ID | Estado | Origen y criterio de cierre |": ID, state, origin and closing criterion) or a task file.
3. Search the notes before any analysis: `a6000/.claude/skills/knowledge-navigation/SKILL.md:21` "python3 scripts/knowledge/search.py ask"
4. Check that an older finding still holds: `a6000/.claude/skills/contradiction-audit/SKILL.md:20` "python3 scripts/knowledge/search.py claim"
5. Analyze through the daemon. Check decisive points against the bytes: `a6000/docs/STATE.md:195` "hallazgos decisivos contra instrucciones y bytes reales"
6. Label each claim: `a6000/work/codex/TASK.md:38` "DESCARTADO / NO VERIFICADO)" (the line lists verified, inference, hypothesis, discarded, not verified).
7. Write the report, the evidence and a test: `a6000/docs/agent/README.md:37` "Informe en `docs/capture/` (+ evidencia en `analysis/`, prueba en `tests/`)"
8. Update the ledgers in a fixed order, then commit by path and push: `a6000/docs/agent/README.md:123` "nunca `git add -A`"

## 8. Weak or unproven

1. Nothing starts, loops, restarts or stops a session.
2. Gates are labels. The count of open claims grows and nothing fails.
3. CI turns failures into skips.
4. Configuration lives outside the repo, and committed files hold one user's absolute paths (`a6000/analysis/rea-independent/bin/rea-avcam.service:6` "ExecStartPre=/bin/rm -f").
5. The state files are large. A brief tells agents not to read them whole: `a6000/.claude/brief-avcam.md:6` "son grandes: usa grep/head"
6. Write scope is prose. The Codex runs had full disk access.
